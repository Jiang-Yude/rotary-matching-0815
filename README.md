# 現場媒合結果頁

活動現場用的單檔投影頁。把 AI 產出的媒合分析結果貼進去，立刻變成六頁可以投影的簡報。

線上版：https://jiang-yude.github.io/rotary-live-matching/

## 這頁在做什麼

活動現場請每位參與者用自己的 AI 寫一段可公開的自我介紹，貼進表單。主持人把收到的資料丟給 AI 做媒合分析，AI 回傳一段 JSON，貼進這個頁面就會排成：

1. 封面
2. 全場分布（領域分類表 + 議題出現次數長條）
3. 交流接點（配對星圖 + 配對表）
4. 重新分組（依共同議題重分的小組卡）
5. 現場點三組（主持人可以直接照唸的口播稿）
6. 收尾

## 怎麼用

1. 開啟頁面，點右下角齒輪。
2. 按「複製請 AI 輸出 JSON 的指令」，貼給剛跑完分析的 AI。
3. 把 AI 吐出來的 JSON 貼回輸入框，按「套用並投影」。

左右方向鍵翻頁，按 F 全螢幕。

貼進去的資料只留在你自己的瀏覽器，不會上傳。投影中不要重新整理，資料會掉；要保險就按「存一份含資料的 HTML」，那份檔案的資料寫死在裡面，重開也還在。

## 配對類型

配對只用四種，AI 不能自己發明：

| 類型 | 定義 |
|---|---|
| 產業鏈 | 一方的產出正好是另一方的投入 |
| 兩兩互補 | 同一群客戶，服務不同，合起來更完整 |
| 客群轉介 | 客群重疊但不競爭，可以互相介紹 |
| 同業互助 | 同一處境，交流方法、分攤成本 |

## 資料格式

```json
{
  "meta": { "kicker": "", "title": "", "lead": "", "chips": ["收到 XX 份"] },
  "distribution": [ { "cat": "領域", "people": ["稱呼"], "n": 1, "topics": "共同議題" } ],
  "topics": [ { "name": "議題", "n": 12 } ],
  "overview": "全場觀察",
  "pairs": [ { "a": "", "b": "", "type": "comp", "why": "", "talk": "", "step": "" } ],
  "groups": [ { "name": "", "members": [], "why": "", "talks": ["", ""] } ],
  "spotlight": [ { "title": "A × B", "lines": ["", "", ""] } ],
  "notes": "風險提醒"
}
```

`type` 只能填 `chain`、`comp`、`ref`、`peer`。頁面對缺欄位有容錯，少給某一段就少顯示那一段，不會壞掉。

## 隱私

這個 repo 裡的預設資料全是虛構的示範人物。真實參與者資料靠現場貼上，不會進到這份原始碼。如果用「存一份含資料的 HTML」存了含真實資料的檔案，那份檔案不要 commit 上來。

頁面本身掛了 `noindex`，搜尋引擎不會收錄。
